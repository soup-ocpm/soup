# ekg

Backend compatibility: **memgraph**. Required packages: `tool_memgraph`,
`tool_storage`. Manifest-level tools: `memgraph`, `storage`, `catalog`. See the
[manifest](soup-package.json) for Python requirements.

An `ekg` object is a graph in Memgraph. The `meta` of a **root** object (an
import or conversion) contains `backend: "memgraph"`, `dataset` (directory on
the volume), `graph_key` (the `memgraph` tool's active-state key for this graph,
a UUID created by `build_ekg` or adoption), `columns`, `mapping` (`event_id`,
`timestamp`, `activity`, `entities`, `values`), `trigger_target`, `counts`,
`process_info` (same shape as the legacy configuration), `date_created`, and
`source_format`.

A **derived** object (e.g. an analysis) has kind `ekg`, its source `ekg` object
among its `parents`, and `meta.state` equal to `{provider, spec}`. The
`provider` key identifies a `StateProvider` contributed to
`ekg.state_providers`, which knows how to apply `spec` to the parent's graph. A
derived object may have another kind (the aggregated `ekg_class` graph); what
matters is `meta.state`. The parent is the first parent that is an `ekg` or is
itself derived; the chain ultimately reaches a root `ekg` with its dataset. An
operation using `derive_state` also supplies `meta.graph_key` on its derived
object.

The public API is `soup_pkg_ekg.api` (for packages listing `ekg` in `requires`).
Callers pass their own `tools`: `build_ekg` requires `memgraph` and `storage`,
while `ensure_loaded`, `derive_state`, and `dispose` require only `memgraph`
because `ekg` reads its dataset files using its own storage.

| `BUILD_STEPS_POINT` (`"ekg.build_steps"`)                                                                                                    | Contribute `EkgBuildStep` with `key`, `order`, `phase`, `applies(ctx)`, and `execute(ctx, db)` using `ctx.contribute(BUILD_STEPS_POINT, step, key=step.key, order=step.order)`. On startup, `ekg` adds folders `/soup/<name>/` containing `<name>_config.json`
that are not yet in the catalog, as `ekg` objects created by `csv_ekg.csv` with
the matching `meta.dataset`. Metadata comes from the config file. An error (e.g.
inaccessible storage) is logged and does not stop the package.

## Building and dataset lifecycle

`build_ekg` has these keyword defaults after `(obj, data, mapping, tools)`:

```text
dataset=None, description=None, all_columns=None, trigger_target=(),
source_format="", save_process_times=False, extra_files=None
```

`save_process_times` remains accepted for compatibility; current builds always
save construction timings. The public types and complete signature are in
[server/api.py](server/api.py) and [server/builder.py](server/builder.py). The
state loader rebuilds Memgraph when switching datasets, so graph reads may
initiate a rebuild. Use the existing operation/lifecycle locks for complete work
and never assume a Memgraph state remains loaded between independent requests.
The host's dataset-bound Cypher adapter uses this package's registered loader.

See the [package developer documentation](../README.md) for authoring, packaging
and lifecycle rules.
